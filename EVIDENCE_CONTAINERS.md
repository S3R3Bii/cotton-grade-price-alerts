# Runtime exports and canonical text

The frozen development receipt and later runtime receipt record hashes of their as-run exports. Windows text output used CRLF for summary JSON; publication canonicalizes text to LF. Their numerical JSON content is identical, but its byte hash differs. The earlier frozen receipt is preserved, not edited to look current. `results/container_verification.json` records both the original runtime hash and current canonical hash, accepting only an exact LF/CRLF representation of the same JSON. All CSV fields, native quotation tokens, cases, thresholds and numerical results are unchanged.

The private evidence retains the later as-run summary bytes and a reconstruction of the earlier CRLF summary that exactly matches its previously recorded SHA-256. The latter is explicitly labeled as reconstructed representation evidence. All 37 frozen files still match their original committed bytes. Public offline replay regenerates inputs and case outputs in separate paths, compares exact CSV fields and JSON content, checks newly generated export hashes and keeps original compressed containers unchanged.

During packaging, the freeze helper initially stopped on an index refresh after text normalization. A subsequent attempted held command also stopped at the mandatory committed-manifest guard, before any summary or score existed. Refreshing the unchanged Git index allowed the actual 37-file freeze commit; only then did later scoring run. This was a working-tree bookkeeping guard, not a repaired numerical result or changed method. The source-market binding failure remains separately retained and disclosed.
